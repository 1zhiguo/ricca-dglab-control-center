## 从源码运行

Windows 安装 Python 3.11 后，在本目录运行 `setup_native.ps1`，再运行 `run_native.ps1`。
`run_native.ps1 --demo` 使用模拟状态，不读取游戏或连接设备。也可用 `build_launcher.ps1`
生成本目录的 EXE 启动器；它需要同目录源码和 `.venv`，不是独立便携发行包。
不要把游戏文件放进公共仓库。开发与贡献说明见 [CONTRIBUTING.md](CONTRIBUTING.md)。

面向 **Holy Knight Ricca English 1.4.1** 的独立 Windows 原生客户端。程序通过
Windows `ReadProcessMemory` 在游戏外部读取遥测，不安装 BepInEx、不注入 DLL、
不修改游戏文件，也不写游戏内存。

当前版本是 **v1.0.0-rc3 实机连接候选版**：包含 DG-LAB Socket 扫码连接。
完成新手教程并保存大于 0 的安全硬上限后，连接成功即按有效游戏状态自动输出，
无需测试 A/B 或单独启用。硬上限仅限制数值，不保证体感安全，请从低值开始。

## 当前功能

原生界面按使用流程拆分为：`设备与游戏 → 个性化范围 → 波形工作台 → A/B 波形监视`。
剧情文本、音频共感和底层诊断分别保留为独立页面。

- 玩家：HP、MP、防御、状态、当前动作名/哈希。
- Boss：交战状态、HP、角色状态和当前动作。
- 场景：Gameplay / ADV、Chapter、暂停、对象重绑和加载状态。
- 剧情：行号、说话人、正文及推进事件。
- 事件：300 ms 聚合掉血、回血、受击、重击倒地、撞墙、防御、hit-stop、碎甲，
  通过玩家/Boss 双动作哈希确认的 Boss catch，以及由 HP 归零与死亡动作哈希双重
  确认的玩家倒下事件。
- 破甲增幅：未破甲时 Pulse ×1.0；本次生命中检测到一次破甲后固定 ×1.2，后续
  破甲不叠加、不计层数。受击、挣扎、音频、败北反馈在最终通道选取后统一乘一次，
  然后受硬上限截断。复活（包括同一玩家对象 HP 0→正值）、从菜单重新进入或游戏
  进程重启后回到 ×1.0；暂停、剧情切换或普通对象重绑不重置。旧护甲层数不会在
  新一轮游戏中自动增加倍率，总览显示“未破甲 / 已破甲”。
- DG-LAB：本机 Socket 服务、局域网地址选择、二维码和手机连接状态。
- 新手教程：首次正常启动自动显示五步引导，依次介绍总览、设备连接、个性化范围、
  波形工作台 / A/B 通道策略，最后必须手动输入 **0–100 的整数安全硬上限**，
  点击“保存并应用”才完成。输入框不会预填，空值 / 越界值不能完成；保存失败
  不会标记完成，也不应用新值。数值和完成状态保存到用户配置，重启后记住。
  尚未完成时禁止设备输出；完成后已连接的设备按有效游戏状态自动输出。
  0 表示禁用所有设备输出；手动暂停及紧急归零仍需点“恢复输出”解除。
  降低上限会下调超过它的档位数值；再次升高上限后可重新选择强度方案。
  左侧“新手教程”可随时重看，打开教程先停止设备输出；演示模式不自动弹教程。
- 启动保护：正常 Windows 客户端使用登录会话内共享命名互斥锁，不同 Python 环境
  或重复双击也只启动一个新版客户端，重复启动尝试切回已有窗口；进程退出后自动
  释放，不留锁文件。首次更新需手动退出旧版窗口，旧版不具备此保护。
- 连接地址：枚举已启用网卡的 IPv4，显示网卡名和完整地址，可“刷新地址”并选择；
  虚拟 / VPN 标记为名称启发式提示，不保证识别所有 VPN。切换地址会更新二维码
  并清空当前输出队列；无需重新完成通道测试。未找到局域网地址时提示本机回环地址限制。
- “连接不上？”提供 Socket / 二维码 / 手机状态、端口占用 PID 和进程名、网卡列表、
  VPN / 防火墙 / Wi-Fi 隔离排查建议，可复制诊断并“重试 Socket”。重试先归零、
  暂停输出，连接后点右上角“恢复输出”；不会结束其他进程或自动修改防火墙 / VPN。
  服务启动失败时明确显示二维码不可用，不再一直显示“正在生成”。小窗口可滚动。
- 右上角固定状态控制：暂停输出 / 已暂停 / 恢复输出；无须独立启用输出，
  游戏暂停不能由此按钮强行恢复。未连接时也可预先暂停，避免扫码后立即输出。
- 游戏 HUD：右上角固定 HUD 开关（默认开、记住设置）。沿用 Manaka 的底部偏左
  A/B 面板：横向锚点 21%–59%，1920×1080 参考高度 68、底边距 24；按游戏客户区
  与 DPI 缩放，随窗口移动和切换屏幕。A 为粉色、B 为青色，显示强度、来源及 32 点
  波形历史，未解锁设备输出时标明“预览”。HUD 只显示状态，不会发送设备命令。
  仅 gameplay / ADV 及具有 ADV 资源的 ATD 剧情显示，主菜单、costume 等其他场景隐藏；剧情时移到
  顶部（同样保留 24 的缩放边距），避开下方字幕，恢复操作后自动回到底部。
  叠加窗透明、鼠标穿透、不抢焦点；切离游戏、最小化、关闭开关或遥测失联时隐藏。
  支持窗口/无边框模式；Windows 独占全屏可能遮挡外部叠加窗，遇到此情况改为无边框。
- 实机输出：连接后自动同步，但仍须通过游戏遥测、构建校验和安全场景检查。
  保存设置会清空旧事件，按新值自动应用；不会解除手动暂停。紧急归零会清空
  波形队列、将两个通道强度设为 0 并保持暂停，重连或保存设置不会自动解除。
- 游戏发现：默认按 `HolyKnightRicca.exe` 进程名自动连接；若自动发现失败，可在
  “设备与游戏”页选择游戏 EXE。程序会保存完整路径、精确匹配该路径对应的运行实例，
  并校验同目录 `GameAssembly.dll` 的 SHA-256；可随时恢复自动检测。
- 通道策略：在“波形工作台”分别打开 A、B 卡片。每个通道独立选择 HP、动作、
  HP + 动作、剧情音频或关闭；分别配置并点击“保存 A/B 通道策略”。
- HP 分级：按绝对扣血量（不是最大 HP 百分比）判断，默认小伤害 ≤3、中伤害
  >3 且 ≤6、重伤害 >6。两条上限可独立调整，支持小数；仍保留 300 ms 聚合窗口。
- 事件配置：每通道的每条规则可独立开关、选择低/中/高档或自定义 0–100 数值、
  波形、0.1–3 秒持续时间。档位跟随“个性化范围”，自定义数值与档位均受碎甲
  升敏和安全硬上限约束。默认轻/中/重 HP 持续时间为 0.8/1.1/1.4 秒。
- 重叠事件：每个通道只保留正在播放的一条。将新事件的目标强度与当前逐渐回落的
  强度比较，更强立即接管，同强度刷新时长，较弱者丢弃；不会相加强度或排队补播。
  两通道互不抢占。暂停、场景切换、对象重绑与紧急停止会清除未结束的事件。
- 波形库：DG-LAB 官方精选、Ricca 受击/撞墙/碎甲/死亡预设，以及可绘制、平滑、
  镜像、归一化并保存的 16 点自定义波形。
- 波形策略：智能分段模式保留每个 Ricca 事件的独立配置；固定预设模式可将当前
  选择的波形一次应用到两通道全部事件。A/B 弹窗分别保存各自的设置。
- 音频共感：独立于事件波形映射，使用 Windows 系统回环或录音输入读取实时电平；
  可设置灵敏度和噪声门限。输出目标由 A/B 通道策略中的“剧情音频”决定，仅在
  ADV 或具有 ADV 资源的 ATD 剧情响应（包括实测藤蔓 3D 剧情）；音频监听总开关
  仍在独立页面，默认关闭。程序不保存录音内容。回环监听的是所选输出设备的全部
  声音，尚未隔离角色语音；BGM 与其他程序声音也可能影响电平。
- 格挡不触发 Pulse：开始防御、格挡命中和未知动作仅保留诊断信息，旧配置也不能
  重新启用格挡惩罚。独立 HP 掉血事件仍按实际伤害处理。
- 通用捕获 / 挣扎：使用捕获对象、允许挣扎开关及进度计数，不依赖特定敌人或动作
  哈希。已核对藤蔓受困、挣扎、逃脱三个状态；其他敌人仍需实机交叉验证。在 A/B
  通道策略选择“动作反馈”或“HP + 动作”，可分别开关“通用捕获开始”“挣扎进度增加”，
  自定义强度和波形（含预览）。“捕获开始”保留低档、默认 1 秒短事件，可调时长；
  “挣扎中”改为持续状态：默认中强度，从受困开始持续至挣脱，不要求按键或进度
  增加，不随时间衰减，不提供时长设置，旧配置的挣扎秒数无效。旧短事件预设迁移
  为中档，已有自定义数值及波形保留。挣扎强度不乘碎甲倍率，仍受安全上限约束。
  计数增加仅记录诊断事件。暂停、加载、读取异常时停止；恢复后只有有效且安全的
  受困遥测才能恢复持续输出，遥测不再刷新时 500 ms 内失效。较强受击暂时接管，
  回落后恢复受困状态基线，不叠加强度。
  捕获对象清空或读取异常时，立即清除捕获 / 挣扎 Pulse，不等待时长结束；
  独立 HP / 受击 Pulse 仍按原规则处理。实际设备停止受遥测、网络及手机调度延迟影响。
  总览新增受困状态、是否可挣扎、进度值和百分比，逃脱后不显示残留满值计数。
  `tests/probe_live_trap.py` 可限时保存最小状态快照；`tests/probe_live_audio.py`
  仅检测电平，不保存声音，不启动设备连接。
- 设备发送：采用每 100 ms 单帧发送，停止时归零并清队列；切换后的新波形将在下个
  设备帧边界生效。0.1 秒是软件事件窗口，实机还受采样、网络和手机调度延迟影响。
  设备发送线程另有 500 ms 更新超时看门狗，Qt 更新停滞时撤销输出并归零。
- 安全门：未知版本、遥测超过 500 ms、断连、未完成教程或硬上限为 0 都禁止设备输出。
  普通映射还受暂停、加载和对象重绑限制；死亡惩罚使用独立的有界优先通道。
- 普通输出暂停：游戏暂停（包括 UI 暂停和剧情 `act_screen_paused`）自动暂停普通 A/B；
  已启用输出时，右上角同一按钮可“暂停输出 / 恢复输出”，无需暂停游戏。暂停
  立即请求 A/B 强度归零并清除两通道队列。保留通道配置，恢复后按最新安全状态继续，
  不补播旧受击；受困持续反馈恢复，音频等待恢复后的新采样。游戏仍暂停时，点击
  恢复不能绕过游戏安全门。快速暂停/恢复先完成清零，再接收新的输出更新。
  普通断连重连自动恢复，但不补播断连期间事件；紧急归零、Socket 异常及发送
  看门狗超时保持暂停，需手动点“恢复输出”，不会因重连或取消游戏暂停而解锁。
  死亡惩罚例外：它优先于游戏暂停和插件普通暂停。右上角会明确显示“死亡惩罚 · 输出中”，
  此时暂停按钮只影响普通反馈，必须用“紧急归零”停止全部输出。异常、失联和硬上限检查仍有效。
  外部读内存无法保证按键同帧停止，实际延迟包含遥测采样、Socket 与手机调度。
- 死亡惩罚：观察到同一玩家 HP 从正值归零时，立即按各通道“死亡惩罚”规则触发一次
  有界 Pulse（默认 2.8 秒），不等待场景入场、不被普通暂停或更强的其他反馈覆盖。
  各通道的规则开关、波形、强度、时长和安全硬上限仍生效。进入后续 CG 不再重复这次惩罚。
- 败北 CG：在同一进程中记录 HP 归零，90 秒内进入匹配的 `ADV/Scene3D_…/` ATD
  场景并连续确认三次有效读数后接管互动；若已记录明确的正值→零 HP 边沿，候选字符串
  缺失也可由实际 Scene3D 资源确认。只有 HP 0 候选而未记录边沿时，沿用入场惩罚规则。
  互动状态为 `NoPlaying` 且动画速度大于 0 时，循环所选波形、保持所选强度；
  返回对话、退出、读取失效、手动暂停时停止循环。不以残留对话文本判断互动。
  同一次流程的子剧本和分镜切换不重复大惩罚。死亡/入场惩罚优先，其余反馈取较强者，
  不叠加强度，始终受硬上限约束。互动循环忽略游戏内部 `is_paused` / pause mask，
  但遵循插件普通暂停、游戏暂停菜单和 `act_screen_paused`；死亡惩罚则优先于这些暂停。
  切场短暂读错会暂停输出但保留败北证据，恢复三次有效读数后继续确认，而不是永久丢失循环。
  A/B 通道策略顶部两条 CG 规则可独立开关、设置档位或自定义强度和波形；
  “关闭”通道不接收 CG。循环按互动状态维持，不设秒数；默认使用中档及官方潮汐。
  游戏无暂停功能时，仍可使用插件“暂停输出”和“紧急归零”。紧急归零不补播已取消的惩罚，
  只恢复当前有效的互动循环。Game Over、断连、读取超时仍归零，安全状态恢复后自动同步。
  中途启动或打开回想模式不会自动认定本次败北。若已在败北互动中重启插件，可在总览
  点“接管当前败北互动”并二次确认；仅对匹配候选的有效互动开放，不补发未记录的死亡惩罚。
  已录制验证 Ghoul 流程；其他特殊 CG 若没有匹配候选或 ATD 字段，保持零输出，需补采。

## 启动原生客户端

在这台开发机上直接双击 `Ricca-x-DGlab.exe`。它只是本地原生启动器，程序主体仍在
本项目目录中，所以不要单独移动 EXE。

也可以执行：

```powershell
.\run_native.ps1
```

如果双击后出现错误，运行 `run_native_debug.cmd`，窗口会保留详细错误信息。

启动演示数据（无需运行游戏）：

```powershell
.\run_native.ps1 --demo
```

若要创建项目自己的 Python 环境，先运行：

```powershell
.\setup_native.ps1
```

这会在本项目建立 `.venv` 并安装 `requirements-native.txt`。不会安装或修改游戏。

## 分发状态

当前里程碑以 `run_native.cmd` 启动，用于首轮实机输出核对。它仍是项目内启动器，
不是可单独复制的最终便携包。通过 Socket 断线、游戏退出、暂停、加载和长时间运行
测试后，再冻结为 v1.0 正式版并生成独立安装包。

## 第一次实机连接与核对

1. 启动游戏并进入可操作场景，再启动 Control Center。若仍显示等待进程，在
   “设备与游戏 → 自动检测失败回退”中选择游戏 EXE；不需要把客户端放进游戏目录。
2. 确认总览显示 `GAMEPLAY-READY`，HP 与游戏 UI 一致，采样率稳定。
3. 依次测试轻击、重击倒地、撞墙反弹与格挡，核对事件只出现一次。
4. 暂停游戏，确认状态变为 `PAUSED` 且 A/B 预览归零。
5. 进入 ADV 剧情，确认说话人、正文、行号随下一句变化。
6. 从剧情回到战斗，等待 6 个稳定样本后才重新出现 `GAMEPLAY-READY`。
7. 扫码前先设置低强度和较低硬上限，确认暂停与急停位置。若不希望连接后立刻输出，
   先点右上角“暂停输出”。不要依赖硬上限保证体感安全。
8. 手机扫码连接后，无需测试 A/B 或额外启用按钮；有效游戏场景会自动同步。
9. 若预先暂停过，点“恢复输出”；先验证一次轻击，再验证重击，核对强度未超过硬上限。
10. 依次验证暂停、进入非战斗场景、游戏退出和手机断线；每一种情况都应立即归零。
    任何异常先点击右上角“紧急归零”，不要继续提高强度。

## 配置文件

事件映射与强度设置保存在：

```text
%LOCALAPPDATA%\Ricca-x-DGlab\settings.json
```

自定义波形逐个保存到：

```text
%LOCALAPPDATA%\Ricca-x-DGlab\waveforms\
```

这些文件独立于游戏和软件版本目录，更新软件不会重写用户数值。成功保存或应用时
显示“保存成功”，写入失败时显示错误并保留原设置。JSON 通过临时文件原子替换，
再次保存前保留上次有效设置为同目录 `settings.json.bak`；主文件损坏时尝试从该备份
读取。自定义波形也存储在上述用户目录，不随更新丢失。

“恢复默认”须二次确认，只恢复通道策略及事件映射，不更改强度、硬上限或音频设置，
不删除自定义波形。音频共感开关及参数为待应用草稿，不受实时遥测刷新影响；点击
“应用音频设置”后才保存并启动 / 停止监听；连接后仍须符合游戏安全门与音频开关条件。

删除设置及其备份后会恢复保守默认值：低 5、中 15、高 25、死亡 25、
硬上限 30；Boss 捕获和音频共感默认关闭。

旧的 `ricca_dashboard.py` 和 `dashboard/` 仅保留作早期调查记录，不再是产品入口。
